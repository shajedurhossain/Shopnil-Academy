Why R for bioinformatics?

Why this matters

R is not just a statistics language — it is the language bioinformatics was built in. Nearly every major genomics method — DESeq2 for differential expression, rrBLUP for genomic selection, edgeR for RNA-seq, Seurat for single-cell data — was first implemented as an R package. If you are doing plant genomics, variant analysis, or GWAS, you will use R every single day. Learning to configure it correctly from the start saves hours of frustration later.

Most scientific programming languages are general-purpose tools that scientists adapt for biology. R is different — it was designed specifically for statistical computing, and the bioinformatics community built Bioconductor on top of it, giving us more than 2,200 packages purpose-built for genomics data. This is why a single command like DESeqDataSetFromMatrix() handles what would take hundreds of lines in Python.

In your thesis work on Sorghum bicolor genomic selection, you are already using rrBLUP and BGLR — both R packages. This module deepens your R fluency so that package is the minimum, not the ceiling.

Install R

Why install from CRAN, not apt?

Ubuntu's default apt repository ships a version of R that may be one or two major versions behind. Bioconductor packages require the latest stable R release. Installing from CRAN's Ubuntu repository guarantees you get R 4.4+ with full Bioconductor compatibility — crucial for packages like DESeq2 and Seurat.

Open your Ubuntu terminal and run these commands one at a time:

📁 Run from: any terminal (no specific folder needed)
Bash — Ubuntu terminal 
# Step 1: add CRAN's signing key so Ubuntu trusts the repository
wget -qO- https://cloud.r-project.org/bin/linux/ubuntu/marutter_pubkey.asc \
  | sudo tee -a /etc/apt/trusted.gpg.d/cran_ubuntu_key.asc

# Step 2: add the CRAN repository for Ubuntu 22.04 (jammy)
# Replace "jammy" with "focal" if you are on Ubuntu 20.04
sudo add-apt-repository "deb https://cloud.r-project.org/bin/linux/ubuntu $(lsb_release -cs)-cran40/"

# Step 3: refresh the package list and install R
sudo apt update
sudo apt install -y r-base r-base-dev

# Step 4: confirm the version — should be 4.4.x or higher
R --version
# R version 4.4.1 (2024-06-14) -- "Race for Your Life"
💡

r-base-dev is essential — it includes the compilers and headers needed to build R packages from source. Without it, many Bioconductor packages will fail to install with cryptic "cannot compile" errors.

You can also install system libraries that many bioinformatics R packages depend on:

Bash — system dependencies 
# Libraries for XML, curl, openssl, image rendering — needed by many R packages
sudo apt install -y \
  libcurl4-openssl-dev \
  libssl-dev \
  libxml2-dev \
  libfontconfig1-dev \
  libharfbuzz-dev \
  libfribidi-dev \
  libfreetype6-dev \
  libpng-dev \
  libtiff5-dev \
  libjpeg-dev

Install RStudio

RStudio vs the R terminal

You can use R purely from the terminal. But RStudio gives you something the terminal cannot — a persistent, visual workspace where your plots, data frames, environment variables, and history all live together. When you are debugging a DESeq2 result at midnight, being able to visually inspect your count matrix in the Environment panel saves enormous time. RStudio is industry-standard for bioinformatics R work.

📁 Run from: ~/Downloads
Bash — install RStudio Desktop 
# Download the latest RStudio .deb for Ubuntu/Debian
cd ~/Downloads
wget https://download1.rstudio.org/electron/jammy/amd64/rstudio-2024.04.2-764-amd64.deb

# Install it
sudo dpkg -i rstudio-2024.04.2-764-amd64.deb

# Fix any missing dependency errors automatically
sudo apt -f install

# Launch RStudio from the terminal (or find it in your app menu)
rstudio &
💡

Check posit.co/download/rstudio-desktop for the latest version number — replace 2024.04.2-764 with whatever is current.

RStudio tour — the four panels

RStudio divides its window into four panels. Understanding what each does will prevent confusion when you start running real analyses:

Panel Location What it does Bioinformatics use
Source Top-left Write and save R scripts (.R files) Your DESeq2 or rrBLUP analysis scripts live here
Console Bottom-left Run R commands interactively Quick tests: dim(counts_matrix)
Environment / History Top-right Shows all objects in memory; browseable history Inspect your count matrix, check sample sizes
Files / Plots / Packages / Help Bottom-right Browse files, view plots, manage packages, search help View your PCA plot; search ?DESeqDataSet
⌨️

Essential shortcut: Ctrl + Enter sends the current line (or selection) from the Source panel to the Console and runs it. You will use this hundreds of times per day.

Configure .Rprofile for bioinformatics

What is .Rprofile?

Every time R starts, it silently reads a file called .Rprofile in your home directory and runs whatever is in it. This is your chance to set defaults that make every R session bioinformatics-ready — setting CRAN mirrors, loading frequently used packages, and configuring how many CPU cores your analyses use.

📁 Run from: R Console (inside RStudio) or terminal
R — create and configure .Rprofile 
# Open your .Rprofile for editing (creates it if it does not exist)
file.edit("~/.Rprofile")

# Paste the following into the file that opens, then save it:

# ── Set CRAN mirror (Germany — closest to Gießen) ──
options(repos = c(CRAN = "https://ftp.fau.de/cran/"))

# ── Show warnings immediately, not at the end ──
options(warn = 1)

# ── Increase console output width for wide data frames ──
options(width = 120)

# ── Disable scientific notation for small numbers ──
# (0.0001 instead of 1e-04 — better for p-values)
options(scipen = 999)

# ── Set default number of threads for parallel packages ──
options(mc.cores = 4)  # adjust to your CPU core count

# ── Quiet startup message ──
options(startup.banner = FALSE)
⚠️

.Rprofile applies to every R session, including non-interactive ones (e.g. scripts run on HPC). Avoid auto-loading packages in .Rprofile — this can cause scripts to fail on servers that don't have those packages. Use library() inside each script instead.

Install Bioconductor

What is Bioconductor — and why is it separate from CRAN?

CRAN is the general R package repository. Bioconductor is a separate, specialised repository maintained by a dedicated team for biological data. It enforces stricter documentation standards, requires all packages to pass automated checks, and releases in synchrony with R itself twice per year. Every major genomics package — DESeq2, edgeR, limma, GenomicRanges, Seurat's dependencies — lives on Bioconductor. You cannot install these with install.packages() alone.

📁 Run from: R Console inside RStudio
R — install BiocManager then Bioconductor core 
# Step 1: install BiocManager from CRAN
# BiocManager is the gateway — it manages all Bioconductor packages
install.packages("BiocManager")

# Step 2: check which Bioconductor version will be used
library(BiocManager)
BiocManager::version()
# [1] '3.19'

# Step 3: install core Bioconductor packages for this course
BiocManager::install(c(
  "Biobase",          # core data structures for genomics
  "BiocGenerics",     # generic functions used by most Bioc packages
  "GenomicRanges",    # represents genomic intervals (chromosomes, positions)
  "SummarizedExperiment", # the main data container for RNA-seq counts
  "DESeq2",           # differential expression (Module 8)
  "edgeR",            # differential expression — alternative to DESeq2
  "limma"             # linear models for microarray and RNA-seq
))

# Step 4: verify installation — should print TRUE
BiocManager::valid()
# All installed Bioconductor packages are current.
💡

Bioconductor installs can take 5–15 minutes the first time because it compiles packages from source. This is normal. You will see many lines of output — the install has succeeded if you reach the R prompt again without an error in red.

Core CRAN packages for this module

Why tidyverse for bioinformatics?

Tidyverse is a collection of R packages (dplyr, ggplot2, tidyr, readr, purrr) that share a common grammar for data manipulation and visualisation. In bioinformatics, you constantly reshape tables — sample metadata, gene annotation files, differential expression results. Tidyverse makes these operations readable and fast. ggplot2 alone is used for nearly every publication-quality figure in genomics journals.

📁 Run from: R Console inside RStudio
R — install CRAN packages 
# Install all CRAN packages for this module in one call
install.packages(c(
  # Tidyverse core
  "tidyverse",    # dplyr + ggplot2 + tidyr + readr + purrr + stringr + forcats
  "ggplot2",      # publication-quality plots (loaded by tidyverse, but explicit)

  # Data handling
  "data.table",   # blazing-fast reading of large genomics tables (VCF, GTF)
  "readxl",       # read Excel files (field data, phenotype tables)

  # Visualisation
  "pheatmap",     # heatmaps for expression data
  "RColorBrewer", # colour palettes for figures
  "ggrepel",      # non-overlapping labels on volcano / MA plots
  "cowplot",      # combine multiple ggplot panels
  "viridis",      # colour-blind-safe palettes

  # Statistics
  "broom",        # tidy output from statistical models

  # Genomic selection (your thesis tools)
  "rrBLUP",       # ridge regression BLUP for genomic prediction
  "BGLR",         # Bayesian generalised linear regression for GS

  # Reproducibility
  "rmarkdown",    # R Markdown for reproducible reports
  "knitr"         # renders R Markdown to HTML, PDF, Word
))

# Confirm everything loaded without error
library(tidyverse)

Your first R session — a genomics warm-up

Why simulate gene expression data?

Before you work with real RNA-seq count matrices, it helps to understand the data structure by building a small one yourself. A count matrix is just a table of integers — rows are genes, columns are samples. The values represent how many RNA fragments were sequenced from each gene. Simulating this lets you understand the shape of the data without needing real FASTQ files.

Create a new R script in RStudio: File → New File → R Script. Save it as lesson-01-setup.R inside a folder called ~/r-genomics-notebooks/.

📁 Save script to: ~/r-genomics-notebooks/lesson-01-setup.R
R — lesson-01-setup.R 
# ================================================================
# Lesson 1 — R & RStudio Setup for Bioinformatics
# Shopnil Academy · Module 4: R Beyond Basics
# github.com/shajedurhossain/r-genomics-notebooks
# ================================================================

# ── 1. Confirm R version ──────────────────────────────────────
R.version.string
# [1] "R version 4.4.1 (2024-06-14)"

# ── 2. Load libraries ─────────────────────────────────────────
library(tidyverse)
library(ggplot2)

# ── 3. Simulate a small RNA-seq count matrix ──────────────────
# Rows = genes, Columns = samples (3 control, 3 treatment)
set.seed(42)  # makes results reproducible

n_genes   <- 200
n_samples <- 6

counts <- matrix(
  rnbinom(n = n_genes * n_samples, mu = 500, size = 1),
  nrow = n_genes,
  ncol = n_samples
)

# Give genes and samples meaningful names
rownames(counts) <- paste0("Sobic.", sprintf("%03d", 1:n_genes))
colnames(counts) <- c("ctrl_1", "ctrl_2", "ctrl_3",
                       "treat_1", "treat_2", "treat_3")

# Peek at the matrix — what does RNA-seq data look like?
counts[1:5, ]
#           ctrl_1 ctrl_2 ctrl_3 treat_1 treat_2 treat_3
# Sobic.001    312    847    421     203     598     714
# Sobic.002      0      1      2       0       1       0
# Sobic.003   1823    992   2201    1560    2089    1834
# Sobic.004    445    220    381     309     422     510
# Sobic.005      7     18      3      12       9       6

# ── 4. Basic summary statistics ───────────────────────────────
cat("Matrix dimensions: ", dim(counts), "\n")
# Matrix dimensions:  200 6

cat("Total counts per sample:\n")
colSums(counts)
#  ctrl_1  ctrl_2  ctrl_3 treat_1 treat_2 treat_3
#  98432  101234   99018   97821  100543   98901

# ── 5. Library size plot ───────────────────────────────────────
# Library size = total reads per sample
# In real RNA-seq, samples must have comparable library sizes
lib_sizes <- data.frame(
  sample     = colnames(counts),
  lib_size   = colSums(counts),
  condition  = c(rep("Control", 3), rep("Treatment", 3))
)

ggplot(lib_sizes, aes(x = sample, y = lib_size / 1e6, fill = condition)) +
  geom_col(width = 0.6) +
  scale_fill_manual(values = c("Control" = "#006A4E", "Treatment" = "#E8B72A")) +
  labs(
    title   = "Library sizes across samples",
    x       = "Sample",
    y       = "Total counts (millions)",
    fill    = "Condition"
  ) +
  theme_minimal(base_size = 13) +
  theme(axis.text.x = element_text(angle = 45, hjust = 1))

# Save plot
ggsave("library_sizes.png", width = 7, height = 4, dpi = 150)
# Saving 7 x 4 in image

# ── 6. Check Bioconductor is working ──────────────────────────
library(SummarizedExperiment)

# Wrap the count matrix in a SummarizedExperiment object
# This is the standard container DESeq2 expects
col_data <- data.frame(
  condition = c(rep("ctrl", 3), rep("treat", 3)),
  row.names = colnames(counts)
)

se <- SummarizedExperiment(
  assays    = list(counts = counts),
  colData   = col_data
)

se  # print the object
# class: SummarizedExperiment
# dim: 200 6
# metadata(0):
# assays(1): counts
# rownames(200): Sobic.001 Sobic.002 ... Sobic.200
# colnames(6): ctrl_1 ctrl_2 ctrl_3 treat_1 treat_2 treat_3
# colData names(1): condition

cat("\n✅ Setup complete — R, RStudio, and Bioconductor are ready.\n")

🔬 Bioinformatics context: The SummarizedExperiment object you just created is the exact format that DESeq2 accepts. When you run a real RNA-seq experiment, your count matrix from STAR + HTSeq-count goes straight into this container. You have just touched the skeleton of a full differential expression pipeline.

Quick reference — setup commands

Command What it does When you need it
install.packages("pkg") Install a package from CRAN Any general R package (tidyverse, ggplot2)
BiocManager::install("pkg") Install a package from Bioconductor DESeq2, edgeR, GenomicRanges, limma
library(pkg) Load an installed package into the session Top of every script you write
packageVersion("pkg") Check what version is installed Reporting versions in papers; debugging
BiocManager::valid() Check all Bioc packages are up to date Before starting a new analysis
sessionInfo() Print full session details (R version, all packages) Always save this at the end of analysis scripts
update.packages(ask=FALSE) Update all CRAN packages silently Monthly maintenance
.libPaths() Show where R looks for packages Debugging "package not found" errors
