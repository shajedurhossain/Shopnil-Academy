What is a genetic variant?

🔬 Why this matters

Every organism's genome is mostly identical to others of the same species — but not completely. The places where one individual's DNA differs from a reference sequence are called variants. Variant calling is the computational process of finding those differences from sequencing data. It is the foundation of population genetics, GWAS, disease gene discovery, and crop improvement.

Imagine you sequence the genome of 100 rice plants. Most of the genome (~99.9%) will be identical across all 100 plants. But at certain positions — perhaps 4 million positions across the genome — one plant carries a G where the reference genome shows an A. That single-nucleotide difference is a variant.

In plant breeding, variants are what creates diversity — different alleles at yield QTLs, disease resistance loci, or drought tolerance genes. Variant calling lets you discover and genotype these differences across hundreds of accessions at once, which is exactly what is done in GWAS and genomic selection pipelines.

Types of variants

🔬 Why this matters

Not all variants are the same. GATK calls different types of variants using different statistical models. Knowing the categories helps you choose the right tool and interpret your VCF output correctly.

Variant type Abbreviation Description Example in biology
Single Nucleotide Polymorphism SNP One base is changed — A→G, C→T etc. Most GWAS markers; SNP chips for genomic selection
Insertion / Deletion INDEL One or more bases are inserted or deleted Frameshift mutations causing gene knockouts
Multi-Nucleotide Variant MNV Multiple adjacent bases all differ from reference Compound substitutions in somatic cancer genomes
Structural Variant SV Large rearrangements (>50 bp): inversions, translocations, CNVs Pan-genome diversity in sorghum; large duplications
Copy Number Variant CNV A region is present in more or fewer copies than expected Gene family expansions in disease resistance genes
💡 GATK HaplotypeCaller is optimised for SNPs and INDELs. For structural variants, you need specialised tools such as Manta, LUMPY, or DELLY. We cover SVs briefly in Lesson 11.

Why GATK?

🔬 Why this matters

There are several variant callers available — bcftools, FreeBayes, DeepVariant, Strelka2. GATK is the dominant choice in human genomics and is widely used in plant genomics because it was designed from the start to account for the statistical noise inherent in short-read sequencing. Understanding its design principles helps you use it correctly.

GATK (Genome Analysis Toolkit) was developed at the Broad Institute. Its key innovation is the HaplotypeCaller, which uses a local de-novo assembly step instead of calling variants position-by-position. This makes it far more accurate for INDELs and complex regions where simple pileup-based callers fail.

Tool Method Best for
GATK HaplotypeCaller Local assembly + HMM Germline SNPs + INDELs, multi-sample cohorts
bcftools mpileup Pileup likelihood Fast, low-complexity samples, prokaryotes
FreeBayes Bayesian haplotype Populations, non-model organisms
DeepVariant Deep learning (CNN) High accuracy on PacBio / ONT long reads
Strelka2 Continuous frequency model Somatic tumour–normal pairs
⚠️ GATK was designed for diploid organisms. If you are working with polyploids (e.g. hexaploid wheat, allotetraploid cotton), the default ploidy assumption will give incorrect genotype calls. Always set -ploidy explicitly for your organism.

The GATK best-practices pipeline — overview

🔬 Why this matters

Variant calling is not a single command — it is a multi-step pipeline. Each step prepares the data so the next step can do its job accurately. Skipping steps (e.g. not marking duplicates or not doing BQSR) leads to inflated false positive rates. Understanding the full pipeline before writing a single command is critical.

🧬

Step 1 — Raw sequencing reads

You receive FASTQ files from the sequencer (Illumina, BGI, etc.). These contain millions of short reads (~150 bp) with associated quality scores.

.fastq.gz
✂️

Step 2 — Quality control & trimming

FastQC checks read quality. Trimmomatic or fastp removes adapters and low-quality bases. (Covered in Module 6.)

FastQC · Trimmomatic · fastp
📍

Step 3 — Alignment to reference genome

BWA-MEM maps each read to the reference genome. The output is a SAM/BAM file — a table of where each read lands on the genome.

.bam · BWA-MEM
🔧

Step 4 — Post-alignment processing

Sort BAM by coordinate. Mark PCR duplicates (Picard MarkDuplicates). Index the BAM. Run Base Quality Score Recalibration (BQSR) to correct systematic sequencing errors in quality scores.

samtools · Picard · GATK BQSR
🔍

Step 5 — Variant calling

GATK HaplotypeCaller runs local assembly at each active region and outputs a gVCF (per-sample). For cohorts, GenomicsDBImport merges all gVCFs, then GenotypeGVCFs produces the final multi-sample VCF.

.g.vcf · .vcf · GATK HaplotypeCaller
🔬

Step 6 — Variant filtering

Apply VQSR (for large cohorts with training data) or hard filters (for smaller datasets or non-model organisms) to separate true variants from sequencing errors.

VQSR · Hard filters · PASS / FILTER flags
📋

Step 7 — Annotation & downstream analysis

SnpEff or ANNOVAR annotates each variant with gene name, functional impact (synonymous, missense, stop-gained). The annotated VCF feeds GWAS, genomic selection, or phylogenetic analysis.

SnpEff · ANNOVAR · annotated VCF

Understanding the VCF file format

🔬 Why this matters

The Variant Call Format (VCF) is the universal output of every variant caller. Every downstream tool — PLINK, TASSEL, GATK filtering, SnpEff, R packages — reads VCF. You cannot do anything with your variants until you understand what the columns mean. This is not optional background knowledge: you will read VCF files every day in genomics.

A VCF file has two sections: a header (lines starting with #) and a data body (one line per variant position).

📁 Example VCF — understanding the structure (no commands to run yet)
VCF 
##fileformat=VCFv4.2
##FILTER=<ID=PASS,Description="All filters passed">
##FORMAT=<ID=GT,Number=1,Type=String,Description="Genotype">
##FORMAT=<ID=DP,Number=1,Type=Integer,Description="Read depth">
##FORMAT=<ID=GQ,Number=1,Type=Integer,Description="Genotype quality">
##contig=<ID=Chr01,length=80884392>
#CHROM  POS     ID      REF  ALT  QUAL  FILTER  INFO         FORMAT  SAMPLE_01  SAMPLE_02
Chr01   14370   rs6054257  G    A    29    PASS    DP=14;AF=0.5  GT:DP:GQ  0/1:14:48  1/1:12:43
Chr01   17330   .          T    A    3     LowQual DP=11;AF=0.0  GT:DP:GQ  0/0:11:51  0/1:9:28
Chr02   1110696 .          A    G,T  67    PASS    DP=10;AF=0.3  GT:DP:GQ  0/2:10:35  1/2:8:27
Column Name Meaning
CHROM Chromosome Which chromosome/contig the variant is on
POS Position 1-based coordinate of the variant on that chromosome
ID Variant ID dbSNP or custom ID; . means no known ID
REF Reference allele The base(s) in the reference genome at this position
ALT Alternate allele The variant base(s) observed in your samples; comma-separated if multiple ALTs
QUAL Quality score Phred-scaled probability that the variant is wrong; 30 = 99.9% confidence
FILTER Filter status PASS = passed all filters; other values = failed filter name
INFO Site-level info Semicolon-separated key=value annotations: DP (depth), AF (allele freq), etc.
FORMAT Sample format Colon-separated keys defining the per-sample fields that follow
SAMPLE_N Per-sample data One column per sample; values match the FORMAT keys (GT:DP:GQ → 0/1:14:48)
🔬 Genotype codes decoded

The GT field encodes which alleles the sample carries. 0 = REF allele, 1 = first ALT allele, 2 = second ALT allele. So: 0/0 = homozygous reference, 0/1 = heterozygous, 1/1 = homozygous alternate. This is exactly the 0/1/2 encoding used in rrBLUP and BGLR for genomic selection — VCF is where those marker matrices start.

3
Connect VCF to genomic selection

In your MSc thesis you use rrBLUP with a marker matrix Z where SNPs are coded as −1, 0, or 1. Explain in 2–3 sentences how the VCF GT field connects to this marker coding, and what preprocessing step is needed to go from VCF to the rrBLUP input matrix.

Show answer

The VCF GT field encodes genotypes as 0/0 (homozygous reference), 0/1 (heterozygous), and 1/1 (homozygous alternate) — which map directly to 0, 1, 2 in an additive numeric coding. To convert to rrBLUP's −1/0/1 coding you subtract 1 (or the mean allele frequency, in the centred version). Tools like PLINK (--recode A) or the R package vcfR can extract the GT matrix from a filtered VCF and produce a numeric matrix ready for kin.blup() or mixed.solve().
